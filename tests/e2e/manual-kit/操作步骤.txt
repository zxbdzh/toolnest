ToolNest 本地完整更新流程手测组合
起始版 0.1.3 → 目标版 0.1.4
组合编号：{{KIT_SHORT}}（完整编号 {{KIT_ID}}）

这两个版本都包含本次修复，使用同一份功能代码，仅版本号不同。
本组合自带本地签名更新源，不需要等 GitHub 发版，不修改正式更新源。
测试安装目录、数据、PATH、自启和凭据命名空间与正式 ToolNest 分开。
更新下载仍由真实 ToolNest 更新器执行，验签、暂存、重启替换和启动确认没有跳过。

一、开始体验
1. 运行 ToolNest-UpdateTest-0.1.3-起始版.exe，按中文安装向导完成安装。
   安装后不会自动打开应用，不用退出正式 ToolNest；本组合会独立运行。
2. 双击桌面「ToolNest 更新测试版 {{KIT_SHORT}}」，或在开始菜单搜索「ToolNest 更新测试版」。
   开始菜单文件夹「ToolNest 更新流程测试 {{KIT_SHORT}}」内也保留「01 打开隔离测试」。
   从安装目录直接双击 ToolNest.exe 会被拒绝，避免漏带隔离参数。
3. 首次引导可以选择“开始时创建首份快照”，或点击“稍后再说”。
   要先验证“未做备份就升级”，请先跳过引导。初始化会创建空目录，不制造快照。
   应用设置中应显示当前版本 0.1.3。首次已关闭自动检查、自动下载，方便逐步观察。
   PATH 列表中的 C:\ToolNestDemo\... 是合成示例，不是你的真实 PATH。
4. 可修改主题、关闭行为或备份计划，保存后再测试升级，核对升级后保留。
   备份完成后可以“查看本次快照”。恢复结果会逐项显示范围，并提供保护快照和“撤回这次恢复…”入口；撤回同样先预览再确认。

二、检查、说明、下载与取消
1. 打开「应用设置 → 更新」，点击检查更新，应发现 0.1.4，并显示中文版本说明。
2. 点击下载更新，应看到下载量、速度与校验状态。本地源故意限速，便于观察。
3. 可以先取消一次，再点击下载。最终应进入「已准备好」状态，显示准备时间及重启入口。
   取消后重新下载可能重新取包，这是正常行为；去重检查指同一份“已经准备好”的包。
4. 此时再次检查更新，不应丢失重启入口，也不应重新下载已准备好的同一版本。
   要精确核对可查看下面「source\stats.json」的 payloadRequests，重复检查前后应不变。

三、完整升级（建议先测试普通退出）
1. 下载准备好后，选择稍后／下次打开生效。应用应继续停留在 0.1.3，不立刻退出。
2. 从应用或托盘菜单选择真正退出。普通退出后不应自己再次打开。
   关闭到托盘不等于退出，托盘隐藏时也不应替换程序。
3. 再点击开始菜单的「01 打开隔离测试」。
   这次应自动应用已准备包、启动 0.1.4，并显示更新完成。
4. 检查刚才的快照、设置和计划仍在。
5. 再次检查，应提示当前已经是最新版本；不能再次下载 0.1.4。

四、再测“立即重启更新”
1. 正常退出本组合的应用（含托盘）。
2. 再运行起始版 0.1.3 安装器。只覆盖本组合的程序，不清空测试快照和设置。
3. 从专用入口打开，确认当前版本是 0.1.3，再检查并下载 0.1.4。
4. 点击重启更新。应先出现确认；取消时留在当前应用。
5. 有未保存设置时应要求先保存或取消修改，不能直接丢弃。
6. 确认重启后应重新打开 0.1.4，并保留测试数据。
7. 目标版 0.1.4 安装器只用于备用直装／覆盖安装；正常升级测试不要提前安装它。

五、错误与恢复（须在尚未准备好目标包的 0.1.3 上测试）
先按第四部分第1～3步回到 0.1.3；没有需要下载的目标时无法复现下载错误。
从同一个开始菜单文件夹依次选择以下故障开关；这些开关后台执行，不弹终端。
开关约150毫秒内生效，点击后等1秒再在应用里重试。

1. 「03 模拟更新源404」→ 在应用内检查更新。
   应显示更新源／HTTP 404 问题，而不是统一说“代理失效”。
   点击「02 恢复正常更新源」后再检查，应恢复正常且清除本次活动错误。
2. 「04 模拟下载失败503」→ 检查并下载。
   应显示服务不可用／HTTP 503，保留当前可用程序。
   恢复正常源后重新检查、下载，应能成功。
3. 「05 模拟签名校验失败」→ 重新检查后下载。
   应明确显示校验失败，不进入可安装状态，不替换当前程序。
   恢复正常源后重新检查，取回正确签名，再下载。
4. 如果已有“准备好”的更新，它应继续可用，源检查失败不应该把它清掉。
   对已就绪包再开启下载故障，不会强迫更新器重复下载，这是本次修复要保证的行为。

六、代理测试（可选）
正常流程默认仅本组合使用直连本地源，不影响系统代理或正式 ToolNest。
也可在本组合应用的「公共代理」里测试 HTTP／SOCKS5：
1. 打开下面 source\fixture-private.json，取 httpProxy 或 socksProxy，以及 username、credential。
   credential 只是本次本地夹具的临时认证口令，不是你的真实代理密码。
2. 在本组合里选择自定义代理，填对应地址、用户名、口令；测试并保存。
3. 检查、下载并完成升级，确认已保存配置延续。
4. 这两个本地代理只能转发本次更新源，不能用来上网或验证你已有代理的公网连通性。
   如要对比这两种协议，可在正常退出后覆盖安装0.1.3，再进行下一轮。

七、数据、证据与重复测试
安装目录：
%LOCALAPPDATA%\Programs\ToolNest-UpdateTest-{{KIT_ID}}
测试应用数据（快照、计划、设置、更新记录）：
%LOCALAPPDATA%\ToolNest-UpdateTest\{{KIT_ID}}\data
本地源状态：
%LOCALAPPDATA%\ToolNest-UpdateTest\{{KIT_ID}}\source

source\stats.json：当前故障模式、下载请求次数、两种代理请求次数。
source\fixture-private.json：本地源及临时代理地址、临时认证口令。
source\server.log：本地源启动错误。
data\updates\switch.json、helper-result.json：更新切换与确认结果（流程开始后才会出现）。
隔离 PATH／模拟自启：
HKCU\Software\ToolNest\Tests\{{KIT_ID}}
这里的恢复操作只针对合成测试值，不触及 HKCU\Environment 或 HKLM 系统 PATH。
自启开关在本组合中是模拟入口，不等于真实登录自启验收。

本地源最多运行4小时；若已过期，先退出测试应用，再通过专用入口重新打开。
停止测试：先正常退出测试应用，再点「06 停止本地更新服务」。
卸载：Windows 设置 → 已安装的应用 → 「ToolNest 更新流程测试 {{KIT_SHORT}}」。
卸载会正常停止本组合的本地源，但不会强制关闭应用。
卸载保留测试数据与隔离注册表，便于重装核对；不会删除正式 ToolNest 或真实 PATH。

边界说明
本次可手测的是同一批修复的真实“本地更新源 → 下载 → 验签 → 重启／下次启动 → 确认”流程。
测试安装器有独立的安装／卸载登记；它不替代正式固定安装目录的升级验收。
不包含 GitHub 线上发版／CDN、正式密钥、Windows Authenticode、真实登录自启或启动失败回退的人工开关。
启动失败回退已在上一轮非输入私有桌面验收；本组合不以篡改已签名程序的方式模拟它。
安装器当前未做 Windows 代码签名，可能出现“未知发布者”；更新归档的验签仍然有效。

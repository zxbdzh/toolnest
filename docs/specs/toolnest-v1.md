## Problem Statement

现有 Path Guard 的界面缺少统一的视觉层次，布局与设置体验需要重新设计。产品结构仅围绕 PATH 备份命名，难以在未来加入其他工具；用户希望保留现有 PATH 保护能力，并形成可持续增加内置工具的桌面工具箱。

旧版将自动备份交给 Windows 任务计划程序执行，与用户要求的“软件自己的计划”不一致。用户还需要明确区分隐藏到托盘与退出，管理自启、失败提醒、历史快照及旧版迁移。

软件需要可以正式安装和升级。自动更新应在后台准备，重启由用户决定；下载可以经过工具箱公共代理，卸载和升级不得丢失快照及用户设置。

## Solution

构建 ToolNest，以 Windows 11 x64 为首版交付平台，采用 Go 与 MyGo 原生 UI。界面参考 mygo-qyin：左侧工具导航、右侧工作区、柔和配色与局部磨砂；优先复用现成控件，通过统一的字体、间距、状态和交互反馈形成精致的桌面体验。

首版提供一个完整的 PATH 工具：查看、搜索、复制、手动及自动备份、快照差异与恢复，不提供 PATH 条目直接编辑。应用内计划在主窗口或托盘运行期间执行，退出与休眠期间暂停，恢复后按规则补跑。

后续功能以内置工具模块随版本更新加入，按需复用设置、网络、计划和执行记录。交付用户级安装包，通过同一公开 GitHub 仓库的 Releases 发布安装包与签名更新文件，支持后台下载、用户控制生效、公共代理、数据保留及旧版迁移。

## User Stories

### 工具箱与界面

## Implementation Decisions

### 1. 产品与模块边界

**已确认（Q02、Q03、Q21、Q25、Q33、Q34）**：产品名 ToolNest；Go＋MyGo 原生 UI；Windows 11 x64；首版只有 PATH 工具；公开源码同仓发布；后续使用内置模块，不引入外部插件安装机制。

**工程细化**：主壳管理工具导航、主题、应用设置和生命周期；PATH 服务管理读取、快照、差异与恢复；公共服务管理计划执行、记录、存储、网络和更新。各工具声明稳定标识、名称、图标、视图和可选的后台任务，按需复用公共服务，不为一个工具创建插件市场或通用脚本平台。

旧 Rust 原型作为行为与数据兼容性依据。业务迁移以 Go 服务为目标，不把旧 GPUI 窗口或外部 Rust 常驻进程包装成新前端。MyGo 版本和锁定依赖在实现时选定并固定；框架升级应通过同一组关键验收。

### 2. 界面与交互

**已确认（Q14–Q18）**：侧栏工具导航、底部应用设置；PATH 页签为当前 PATH、快照、自动备份。宽窗口左右展示用户／系统 PATH，分隔线可拖动、独立滚动；窄窗口切换范围。默认跟随系统，保留浅色与深色选择；侧栏和顶栏轻磨砂，正文实底；正文约 14 逻辑像素，行高约 36–40 逻辑像素。

**工程细化**：

- 优先使用 MyGo 的表格、分栏、输入、选择、开关、提示和弹窗；必要时在现成交互基础上封装外观，保持键盘操作、焦点与禁用行为。
- 视觉采用柔和中性色、一个克制的强调色、清晰字阶与细边；参考项目只作为风格和交互依据，音乐封面、问候横幅等不进入工具界面。
- 顶栏承载页名、刷新和备份等实际操作。状态显示真实数据，首页不填充未实现工具或虚构指标。
- 当前 PATH 保留原始序号；长路径可横向滚动或展开完整值，复制取得完整原值。搜索只改变展示，不排序、合并或重编号。
- 快照页采用列表与详情结构，显示时间、来源、范围、差异及恢复入口；当前差异与恢复预览分别明确方向，避免把新增／移除的含义颠倒。
- 自动备份页显示启用状态、模式、下次运行、最近结果及执行记录；错误摘要说明原因和下一步，可展开技术详情。
- 控件反馈以短时颜色、透明度和轻微按压变化为主，避免整页统一入场。减少动态效果或材质不可用时提供稳定的静态／实底界面。
- 窗口尺寸、切换断点与侧栏宽度以实际可用工作区验证；缩窄后不能丢失选择、搜索或未保存的设置草稿。

### 3. PATH 原始语义与快照

**已确认（Q03、Q06、Q07）**：查看用户与系统范围、搜索复制、手动及自动备份、差异、恢复；不直接编辑条目。自动与补跑无变化时只记检查结果，手动始终保存；快照全部保留，手动清理。

**工程细化，继承旧版已经存在的语义**：备份对象是注册表中的 PATH 值，不是其指向的目录，也不是当前进程继承的环境副本。保留注册表字符串类型、原始 UTF-16LE 字节、值是否存在；不展开变量、不修剪空白、不去重、不排序。缺值、空字节和空字符串不能合并。显示解码不参与恢复写入。

| 数据概念 | 必须保存的信息 | 对外约束 |
| --- | --- | --- |
| 快照 | 格式版本、稳定标识、创建时刻、来源、两个范围的原始状态 | 新写入有格式版本，旧版无版本数据由兼容读取器识别 |
| 范围状态 | 存在性、类型与原始字节 | 字段缺失是格式错误，不能当成需要删除该值 |
| 计划 | 模式、参数、启用状态、修订、下次到期与最近结果 | 重新启动不会重置到期时间或凭空制造漏跑 |
| 执行记录 | 操作、触发来源、起止时刻、结果、关联快照与错误摘要 | “无变化”是成功检查，不能显示为备份失败 |
| 保护快照 | 恢复前原始状态与操作关联 | 不受自动去重影响，可在历史中明确识别 |

快照成功落盘、可读且校验通过后才能报告备份成功；失败或中断的暂存文件不作为有效快照。一个范围读失败时不能把它写成缺值，也不能报告两者备份完整成功。

自动比较使用当前两个范围与最近一份有效、可比较快照的完整原始状态；没有有效快照则保存。只与最近状态比较，保留 A→B→A 的真实变化。重复项、空条目、顺序、存在性和类型变化均可构成差异；默认展示不能掩盖这些变化。

清理先展示选中的具体快照和数量，再确认；默认不选中任何快照，不能借“全部保留”之名自动实施轮转。保护快照与普通快照同样遵循用户主动清理。格式损坏的文件可报告，但不自行删除。执行记录默认持久保存，首版不另加自动清理策略。

### 4. 恢复流程与权限

**已确认（Q08–Q10）**：默认仅用户 PATH；系统范围主动勾选；一个弹窗选择范围、预览差异并确认；恢复前必须保存保护快照，失败则不写入。系统恢复按需授权，取消则整次取消，主界面保持普通权限。

**工程细化**：恢复按以下外部行为执行。

1. 验证快照格式与范围，读取当前状态，生成清楚的恢复方向预览。没有选择范围时不可提交。
2. 用户确认后取得所选范围需要的权限；若系统授权取消或失败，在任何 PATH 写入前结束整次操作。
3. 重新核对当前值与预览时是否一致；若已变化，刷新预览并要求重新确认，不覆盖用户没有看到的变更。
4. 将写入前原始状态保存为新的保护快照；即使内容与已有快照相同也保存。落盘失败时不继续。
5. 按范围写入并读回原始状态验证。恢复缺值仅删除对应的 PATH 值，不能删除整个环境键。
6. 如写入失败，对本次已改动范围尽力回滚并再次读取结果；明确区分“未写入”“已回滚”“部分恢复／回滚未完成”，保留保护快照和处理入口。
7. 成功后广播环境变更；通知失败与数据写入失败分开报告，提示已启动的终端可能需要重开。

用户与系统范围不存在跨位置原子提交保证，回滚也不能承诺绝对成功。若检测到其他程序介入修改，不以盲目重试覆盖其状态；停止并报告当前状态。对恢复写入不自动重试。

提权助手只接受本次已确认的恢复范围和快照内容，校验调用者与请求；不能提供任意命令或任意注册表写入接口。用户范围始终指向原始发起用户，不能因使用其他管理员凭据而落到另一个账户。助手完成或取消后退出，不能变成管理员常驻进程。

### 5. 应用内计划

**已确认（Q04–Q06、Q22–Q24）**：默认关闭，预填每 6 小时；间隔与每日定时择一；托盘继续，退出、关机或休眠暂停；漏跑合并补一次；无变化跳过快照；失败通知且相同错误合并；5 分钟后最多重试一次。

**工程默认值与时间语义**：

- 首版一个 PATH 计划，备份两个范围；间隔接受 1–168 的整数小时，预填 6。每日模式使用系统本地时间，要求选择有效时刻，输入精度为分钟。
- 首次开启时立即检查一次当前状态，按自动去重规则保存；随后按所选模式计算下一次到期。只修改草稿不生效，保存时明确显示下次运行时间。
- 间隔从启用或修改计划的时刻计算，使用持续经过的时长；每日定时按本地日期与时刻计算。手动备份不推迟原计划。
- 重新打开、休眠唤醒或发现时钟变化时检查持久化到期记录。已启用期间错过的多个时间点合并一次，之后推进到未来的下一次时间点，不逐个补历史。
- 暂停计划期间不累计漏跑；重新启用视为新的启用时刻。启动不把已禁用计划擅自打开。
- 每日定时对同一本地日期的正常计划最多执行一次；时钟回拨或夏令时重复时刻不重复触发，跳过的时刻在恢复可用后合并检查一次。时区变化后重算并展示下次时间。
- 每次计划到期的执行结果与下一次到期需持久保存。失败只安排一次延迟重试，重试失败不会继续递归安排；退出或关闭计划取消尚未执行的重试，失败记录保留。
- 重启后依据持久化的下次到期处理补跑，不通过重启重置同一次失败的重试预算；正常计划与已安排重试冲突时合并，不能并发重复备份。

时钟、计算下一次时间与执行器相互分离，以可控时间验证睡眠、时区与跨日，不在测试中真的等待数小时。自动备份不注册 Windows 任务、不创建后台服务、不唤醒计算机。

### 6. 生命周期、忙碌状态与记录

**已确认（Q11–Q13）**：可跳过首次引导；自动备份与自启默认关闭；开启自启后默认进托盘，手动启动显示窗口；关闭先询问，可记住并在设置中修改。

**工程细化**：

- 当前用户单实例。第二次手动启动唤回已有窗口，不创建第二个调度器；更新或提权助手有受限入口，不能作为第二个普通实例运行。
- 托盘菜单提供显示主窗口、立即备份、打开设置及明确的退出；托盘显示真实运行／错误状态。托盘不可用时保留窗口并说明原因，不能隐藏成无法找回的进程。
- 设置草稿确认后才持久保存；取消引导或弹窗不保存。关闭弹窗的“记住”默认未勾选，取消关闭不改变偏好。引导被跳过后不每次启动重现，原设置仍可从应用设置修改。
- 对备份、恢复、导入、目录切换及程序替换统一协调，读写状态和设置不能相互穿插而产生半成品。后台任务不阻塞绘制与交互。
- 用户请求退出或更新重启时，正在执行的关键写入先完成或安全失败；提供等待／取消退出的反馈，不提供中途强杀写入的应用按钮。恢复前的预览或授权可以取消，已开始的写入不伪装成可瞬时撤销。
- 计划在忙碌期间到期最多留下一个待执行检查，结束后按当前配置执行；已取消或修改的计划不能执行旧修订任务。
- 自动失败按连续同类问题合并通知，恢复成功后重新允许未来新故障提醒；通知不可用时应用内仍显示错误。不强制弹主窗口。
- 成功、失败、无变化、取消与部分完成分别记录；界面更新应对应实际完成结果，不能同时显示“成功”与未处理的失败。详细日志避免包含代理密码和整段个人 PATH。

### 7. 数据保存、导入与目录切换

**已确认（Q19、Q20、Q30、Q32）**：按当前用户保存数据，快照可改目录；旧快照检测后确认复制导入，保留原文件和原始时刻；目录切换复制校验后生效，失败继续原目录；卸载保留用户数据。

**工程细化**：应用偏好与执行记录留在用户数据根，快照使用当前配置的独立目录。写配置采用可恢复的原子替换；目录不存在、不可写或暂时离线时清楚报错，不静默改用其他目录，也不把空结果显示成全部历史已丢失。

旧版检测仅针对已知旧数据位置，不扫描整盘。导入前统计可识别文件，确认后逐份校验和复制，保留旧格式读取能力及来源记录。相同标识且内容相同的重复导入跳过；同标识不同内容单独报告冲突，不能覆盖。内容相同但时间／标识不同的历史快照仍保留，不能套用自动备份去重删除历史。损坏或不支持文件保留原件，结果汇总成功、跳过和失败数量。

更换快照目录先校验目标，再列出源、目标和待复制数量。只枚举当前快照目录已识别的快照，不递归复制任意子目录；相同位置为无操作，重定向或重叠目录不能造成无限复制。复制后校验原始数据、持久保存新位置，全部成功才切换；原文件不删除。失败保留原配置，报告已产生的副本，不覆盖目标未知文件。

旧版缺少可靠机器／账户身份信息的快照，导入不等于自动授权恢复到任意账户；实际恢复仍按原始发起用户及明确范围确认。首版不提供跨机器同步或自动云上传。

### 8. 旧版自动运行入口

**已确认（Q31）**：核实旧版归属后提示，用户选择并确认停用；保留恢复信息、旧程序和快照；无法确认归属的项目不动。

**工程细化**：检查任务／自启项的用户、执行文件、参数及旧版标记，名称只能用于定位。变更前重新读取并确认未被其他程序改动。计划任务优先禁用而非删除；自启入口保留足够信息，以便用户主动撤销停用。撤销时也需核实当前归属，不能覆盖后来变化的配置。

导入快照、停用旧入口与启用新计划是独立操作。迁移不结束用户现有进程，也不卸载旧程序。针对当前原型曾出现的同名任务冲突，只记录“归属未确认”，不推断为可删除的旧任务。

### 9. 公共网络与代理

**已确认（Q28、Q29）**：代理作为工具箱公共网络设置，更新及未来联网工具默认共用，可填写代理地址，不改 Windows 系统代理。

**工程细化**：提供跟随系统、直连、自定义三种模式，默认跟随系统。自定义首版目标支持 HTTP 代理与 SOCKS5 地址，校验协议、主机和端口；不支持的协议明确拒绝。可选代理账号密码分开输入，密码使用当前用户的系统凭据存储，不明文写日志、错误详情或公开文件。

跟随系统复用框架支持的系统／环境代理规则，环境变量优先级在帮助中说明；直连和显式自定义模式不能再被环境变量覆盖。更新检查、版本说明及下载重定向均经过同一网络配置。自定义代理连接失败不能静默直连；重定向不向目标站转发代理凭据。

提供连接测试，显示实际检查的更新入口与错误类型，不仅检测本地端口是否开放。失败不阻止离线 PATH 功能。配置修改原子生效，新请求使用新配置；正在下载的请求可取消后按新配置重试，不能同时混用两套策略。上述协议、凭据和代理适配属于待实现验证的目标，不声称 MyGo 默认已经替应用完成这些接入。

### 10. 安装、升级与卸载

**已确认（Q26–Q30、Q33）**：Windows 安装包、开始菜单与卸载入口；自动后台检查和下载，用户决定重启或下次启动生效；同一公开仓库 Releases；卸载保留快照、设置和记录，移除本软件自启项。

**工程细化**：优先使用 MyGo 的 NSIS 当前用户安装器、更新校验与原生 UI 能力。安装保持稳定标识和程序位置，数据与程序分离；日常安装与更新使用当前用户权限，系统 PATH 恢复的提权单独处理。安装器不修改用户 PATH，也不自动启用自启或备份计划。

更新默认检查稳定发行版：启动后延迟约 10 秒检查，运行期间每 24 小时检查一次；提供手动检查及关闭自动检查／下载的设置。检查频率与 PATH 备份计划彼此独立。首版不提供预览渠道切换。

更新状态至少表达未检查、检查中、最新、发现新版、下载／校验中、已就绪、等待安全切换、失败。展示当前版本、可用版本、最近检查及用户可读的版本说明；检查失败不能显示为已是最新。重复点击不创建并发下载。

签名更新归档及差分包使用应用内置公钥验证，发布私钥只在发布环境保存；校验失败拒绝替换。增量不可用时使用完整包，不自行实现签名算法。Windows 安装器代码签名与更新包签名分别配置和验证，不能混为一谈。

后台下载与真正替换程序分开控制。备份、恢复、导入、目录切换期间可以检查／下载，但不可替换程序或重启；准备完成后提示。选择稍后继续当前版本，正常退出或下一次启动的安全阶段完成切换；隐藏到托盘不当成退出，不偷偷重启。重新启动恢复窗口／托盘状态和未变的计划配置。

更新失败保留当前可用版本和用户数据，输出可执行的重试入口。借鉴 Magpie 的旧程序保留及启动确认机制，对无法启动的版本停止自动循环尝试，并支持明确失败状态；需通过故障演练证明回退行为，不能把进程启动握手当成所有功能已经健康。若回退失败，准确给出保留副本与人工恢复入口。

**实现前技术检查**：官方更新 API 在 Windows 会替换程序文件，安装器钩子不会随自更新执行。必须在所选依赖版本中确认如何实现公共代理、下载暂存、忙碌阻止切换、启动失败回退及多文件更新一致性；完整插件无法满足时，复用其底层更新能力和现成 UI 控件补充应用协调。不能为了套用默认插件而放弃用户控制重启或关键写入保护。

自更新后同步必要的版本登记与运行入口；安装器覆盖升级也要检查本应用是否忙碌，不能强杀恢复任务。卸载只移除明确属于本应用的程序、快捷方式、卸载登记和自启入口，保留全部用户数据及自定义快照目录，不恢复或清理当前 PATH。重新安装后读取保留数据，自启显示实际系统登记状态，不能因残留偏好而静默重新注册。

### 11. 发布与文档

已确定公开源码同仓管理规格、issue 与 Releases。使用语义版本号，源码版本、安装包、更新元数据及界面版本保持一致；发布产物全部验证后才公开更新入口，避免指向不完整版本。用户版更新日志只写可感知变化、修复与必要操作。

首版正式交付需要从一个已安装版本升级到另一个可区分的测试版本，不能用开发构建通过编译替代升级验证。发布私钥、个人快照、真实运行数据、代理凭据及含个人路径的截图不进入公开仓库或测试样本。

## Testing Decisions

**已确认（Q35）**：采用完整流程验收，安装、代理和自动更新属于首版完成条件。恢复写入在隔离环境或专用测试注册表进行，不对开发者当前真实 PATH 做破坏性验证。

### 测试边界与已有依据

以应用服务／用户操作入口作为主要行为测试边界，使用真实的本地临时数据目录，替换时钟、注册表访问、桌面事件和网络来源来构造故障。仅对确实需要的外部依赖建立小接口，不为每个函数添加 mock 层。

旧原型已有原始字节与缺值区分、异常快照拒绝、重复项／顺序差异、搜索保序、关闭偏好持久化等测试，可作为迁移语义基线。使用合成旧格式样本验证 Go 读取器；旧测试通过与否不作为新实现通过的证据。旧 Windows 任务调度测试不沿用为新计划验收。

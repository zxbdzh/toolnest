# 使用 MyGo 构建可扩展的桌面工具箱

用户在 2026-11-12 明确要求将原来的 PATH 专用工具调整为可承载后续功能的工具箱，并指定使用 MyGo，优先采用现成控件、提升界面精致度。本项目据此采用 MyGo 作为新产品框架；原 GPUI/Rust 实现保留为功能和数据格式的参考。

用户在 Q34 明确选择 Go 与 MyGo 原生 UI，优先使用现成控件并按需封装外观，不采用 WebView 页面路线。现有 Rust 业务代码如何迁移需要单独设计，不能把框架切换视为简单换皮。

用户随后确认首版只完成 PATH 的查看、备份、差异和恢复，不提供条目直接编辑；后续工具以内置模块随软件更新加入，按需复用导航、设置、计划及执行记录，首版不实现外部插件安装机制。界面以 mygo-qyin 为风格参考。

旧版快照检测后提示用户确认复制导入，保留原文件与原始时间；新产品按用户保存设置和数据。用户另确认安装包、自更新、公开源码并在同仓管理 Releases，具体签名与发布配置继续收敛。

参考：[MyGo 官方文档](https://mygo.run/docs)、[MyGo 原生组件目录](https://github.com/egoist/mygo/blob/main/docs/ui/README.md)。

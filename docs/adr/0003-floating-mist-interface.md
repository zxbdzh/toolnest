# 浮光布局与雾蓝银白正式界面

日期：2026-11-13。状态：用户确认，正式 UI 已实现；分层验收通过与剩余边界见 [验证范围](../validation.md)。

## 决定与来源

用户先选择「浮光」的布局，比较独立配色原型后明确要求：「雾蓝银白不错，就用浮光的布局配这套颜色，开始改正式界面吧，控件尽量用现成的，改完完整验收，别抢我窗口焦点。」这项决定覆盖 v1 规格中主壳采用左侧栏的旧展示决定，不改变 PATH、快照、计划、代理和更新的业务边界。

- 默认首页改为工具空间；顶部胶囊导航通往 PATH、快照、自动备份，设置入口位于右上角。
- 采用银白／灰蓝色阶，主操作为 `#416B8C`，深浅主题分别定义高对比文字与实底正文。
- 首页使用实际 `app.View` 的条目数、可用快照、下一次运行时间与代理模式。损坏快照不计入可用保护数，不固定演示时间或虚构运行状态。
- 继续使用 Go＋MyGo 及现成控件；纯 SVG 装饰通过 MyGo Image 绘制，不增加浏览器或 WebView。
- 不引入没有持久化约定的收藏开关，不将静态演示的假功能直接带入正式程序。

## 保持不变

`app.Actions` 接口、只读 PATH 原始语义、恢复预览令牌、保护快照、业务写入互斥、计划持久化、代理凭据保存、托盘生命周期和更新签名机制保持原样。公共代理入口只定位已有设置，不乐观修改或自动保存。

## 验收约束

测试优先通过 MyGo NewTester 在内存渲染，再用独立的非输入桌面执行真实 UIA 与 PrintWindow。测试不得激活前台窗口、切换输入桌面或注入用户桌面的键鼠。安装／卸载、UAC、真实托盘及已安装更新链路需要符合隔离约束的执行环境，无法安全执行时明确记录阻塞，不以普通测试通过替代。

用户随后明确由当前会话直接继续后端检查与剩余验收，不再委派其他助手。沿用已经实现的业务接口，仅在有可复现失败时最小修复；不把助手路由作为交付阻塞。后台桌面已执行真实入口升级确认、托盘启动请求下的确认和失败回退；这不等同于真实通知区域托盘或已安装应用全流程通过。

## 产品细节打磨

用户随后反馈正式软件仍显简陋。本轮保留已确认的浮光布局、雾蓝银白和 MyGo 技术栈，收敛重复装饰、增大正文与操作字号，用银灰背景与实色面板建立层次。设置改为桌面分类导航与限宽内容区，窄屏继续使用原生分段控件；工具入口、快照摘要、备份实际状态和更新操作按真实数据组织。没有扩展 v1 功能范围或更换框架。

开发期间的 0.1.x 为本地 TEST-ONLY 预览包；公开版本从 0.0.1 开始。无窗口截图不视为系统材质验收，具体边界见 [验证范围](../validation.md)。
